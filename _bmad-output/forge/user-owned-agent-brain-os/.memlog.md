goal: 压力测试产品是否成立，并收敛第一个值得构建的产品切口

- (crack) 当前定位把用户痛点与实现架构混在一起：可插拔 Brain OS 是方案，不是尚已验证的首要购买理由。第一步必须锁定用户愿意安装、授权并持续使用它所解决的单一高频失败。
- (lock) Agent 是可替换的执行介质；用户长期拥有的核心资产是独立于任何 Agent 厂商的知识、记忆与工作连续性。产品必须允许替换 Codex、Claude Code、Hermes 等 Agent，而不丢失这些资产。
- (direction) 日常价值由跨 Agent 切换时的连续工作驱动；供应商停服或限制访问属于低频但决定用户信任与数据主权的退出保障。
- (crack) 仅保证记忆文件和知识库仍然存在，并不等于替换 Agent 后可以继续工作；还需明确哪些状态、规则、技能和上下文语义必须可移植。
- (direction) 产品面向人的长期数字大脑，而不只面向软件开发：同一用户会在开发、个人兴趣及其他领域使用不同 Agent，并持续产生领域知识和记忆。
- (crack) 若把所有领域记忆放进一个扁平全局池，个人兴趣会污染开发上下文，工作机密也可能泄露给不应访问的 Agent；必须定义隔离、继承和跨域共享规则。
- (assumption) 当前候选模型是一个用户身份下拥有共享个人核心、多个领域空间、各领域下多个项目与任务；只有明确允许的记忆才从下层提升或跨域共享。
- (lock) 默认共享规则确定：只有个人核心可默认跨领域共享；领域、项目与任务记忆默认隔离，需明确提升或授权才能跨域使用。
- (lock) 产品不得强迫用户采用统一的记忆分类或单一后端；必须适配不同记忆项目、知识库项目以及 Codex、Claude Code 等 Agent 自带记忆，并提供跨源统一管理和搜索。
- (direction) 目标体验：用户查询某个项目时，系统可同时搜索 Codex、Claude Code 及已连接知识库中的相关内容，保留来源并汇总为统一结果。
- (crack) 纯联邦搜索依赖原始 Provider 持续可用，与 Agent 可替换、资产不随厂商消失的核心原则冲突；必须决定哪些内容只索引、哪些内容复制归档、谁是权威源。
- (lock) MVP 首先解决只读可见性：用户能够知道 Codex、Claude Code 等各 Agent 中分别存有哪些记忆，并可查看来源；暂不承担跨 Provider 的统一写入、修改或同步。
- (direction) 第一阶段候选产品形态是跨 Agent 记忆资产盘点与搜索工具：连接、发现、索引、搜索、来源追踪，后续再演进为记忆治理层。
- (crack) 必须界定第一版所称的记忆：Agent 明确保存的长期记忆、项目指令与记忆文件、会话摘要、原始聊天记录并非同一类资产；若全部纳入会产生噪声、隐私和规模问题。
- (lock) MVP 首批只接入 Codex、Claude Code、Hermes 和 OpenClaw 四类 Agent。
- (lock) MVP 对接并展示 Agent 已抽取、保存的全部相关记忆资产；原始聊天记录不作为记忆进入默认展示和搜索。
- (direction) 聊天记录仅可作为记忆来源证据或未来重新抽取的原料，默认不摄取、不索引、不展示在记忆结果中。
- (direction) 产品需要在四类 Agent 记忆解析之上提供可视化浏览、统一搜索和来源定位。
- (crack) 四类 Agent 对记忆的存储位置、格式、可访问接口和语义可能不同；在承诺全部对接前，必须逐一完成真实数据源与能力审计。
- (lock) MVP 采用完全本地优先形态：本地服务加本地 Web 可视化界面，记忆内容默认不上传云端。
- (direction) 本地运行既是四类 Agent 本机数据访问的实现条件，也是用户拥有数据、避免新平台锁定的产品信任基础。
- (lock) MVP 统一搜索返回带 Agent、来源、项目、时间与原始位置的记忆卡片，不自动生成总结答案；AI 汇总留作后续可选能力。
- (direction) 搜索界面必须允许按 Agent、项目、来源和时间过滤，展开原始内容、定位原始文件，并暴露无法读取的来源以及疑似重复或冲突。
- (lock) MVP 接入流程采用自动发现、用户确认、只读索引，并支持手动添加路径或连接器。自动发现阶段只识别来源与元数据，不在用户确认前摄取内容。
- (direction) 高级用户能够查看每个连接器实际读取的路径、解析状态与权限边界。
