topic: Tessera 本地优先跨 Agent Memory 联邦规范
updated: 2026-07-20T18:09

- (direction) MVP 先服务个人开发者 Carver 的本机开发工作流，后续再扩展为可下载本地产品与多知识源联邦。
- (capability) CAP-1 自动发现 Codex 与 Claude Code Candidate Source；success 是启动后展示 Provider、候选路径、发现依据与可判定 Native Project，且不读取聊天记录。
- (capability) CAP-2 用户逐个确认、拒绝或停用 Source；success 是只有 Confirmed Source 进入正文扫描，确认状态重启后保留且不改变原始记忆。
- (capability) CAP-3 展示 Source Inventory；success 是每个 Source 显示 Provider、路径、Native Project、Coverage Level、Source Health、最近成功扫描、记录数与错误。
- (capability) CAP-4 保留 Provider Native Project 并支持 Tessera Project 映射；success 是跨 Provider 映射只写入本地状态，不猜测未确认项目，不修改源数据。
- (capability) CAP-5 限定并读取 Agent Memory；success 是原始聊天、transcript、CLAUDE.md、AGENTS.md、规则文件等排除，纳入记录标明 Provider Memory 类型。
- (capability) CAP-6 只读建立、更新和重建 Derived Index；success 是源文件不被修改，失败扫描不替换上一成功版本，删除索引后可从 Confirmed Source 重建。
- (capability) CAP-7 跨 Provider 搜索和筛选；success 是可在全部或指定 Confirmed Source 中按 Provider、Source、Tessera Project、Native Project、类型与时间组合筛选，并区分空结果、未索引和不可用。
- (capability) CAP-8 展示原始片段与 Provenance 并打开原始位置；success 是结果包含 Provider、Source、Native Project、原始文件或引用、定位、更新时间、Coverage Level 与 Source Health，且不生成摘要冒充事实。
- (capability) CAP-9 隔离 Source 故障并支持恢复；success 是单个 Connector 失败不阻断其他 Source，旧索引保持可查询，用户可重新扫描并看到原因与上次成功时间。
- (capability) CAP-10 浏览 Agent Memory 集合与结构；success 是用户可按时间、Native Project、类型浏览，并从集合或结果打开原始记忆位置。
- (capability) CAP-11 本机离线使用；success 是无账号、无联网依赖可启动、发现、索引、搜索、筛选、浏览和打开来源。
- (constraint) Agent Memory 原生文件是事实源，Tessera 只读；Derived Index 必须可删除、可重建，不能反向写入 Provider。
- (constraint) MVP 只支持 Codex 与 Claude Code 的自动发现来源；不提供任意目录手动添加。
- (constraint) Tessera 运行正常时不得上传 Agent Memory、搜索词、项目映射或诊断数据，日志默认不记录正文、查询词和凭据。
- (constraint) 只读取用户确认的 Source；路径、符号链接、权限或来源身份变化必须重新校验。
- (constraint) 展示内容按不可信文本处理，不执行 HTML、脚本或命令。
- (constraint) 扫描只有完整成功才能切换可见 generation；失败保留上一成功索引，单 Source 故障隔离。
- (constraint) watcher 只能触发 reconcile，不能直接改变可见索引；搜索与浏览共享同一 Derived Index 和健康状态。
- (constraint) Source identity 使用持久 source_id 与版本化确定性 fingerprint；歧义来源不得自动合并，必须显式 rebind。
- (constraint) generation 使用 source revision、fencing token 与 snapshot-at-validation；dirty_after_validation generation 不得激活。
- (constraint) 核心发现、搜索、筛选、来源打开必须支持键盘操作；性能阈值以真实数据基准为准，不预先编造。
- (constraint) Agent Memory 与未来 Knowledge Source 是不同领域类型；MVP 不加入 Obsidian、RAGFlow、飞书知识库的实现或 UI。
- (constraint) 实现采用 Tauri 本地桌面壳、Rust 核心、React/TypeScript/Vite UI、SQLite FTS5 派生索引；精确 patch 与构建门禁由 Phase 0 锁定。
- (non-goal) 聊天记录、session transcript、人工规则文件的抽取或索引。
- (non-goal) 自动摘要、语义推理、写回、冲突解决或统一记忆后端。
- (non-goal) Hermes/OpenClaw、Obsidian、RAGFlow、飞书知识库 Connector。
- (non-goal) 云端、多设备、移动端、团队共享、权限协作、MCP/CLI/HTTP 服务。
- (assumption) 首个真实用户是 Carver，MVP 运行在其本机 macOS 开发环境。
- (assumption) Codex 与 Claude Code 的受支持记忆格式会通过 fixtures 和 parser version 管理，格式漂移显示 degraded 而非静默漏读。
- (question) Phase 0 应锁定的 Tauri exact patch、Rust toolchain、macOS 最低版本和签名/安装策略是什么？
- (question) 真实数据基准完成后，搜索延迟、首次扫描、内存和索引体积的可接受阈值是什么？
- (question) 用户是否需要在后续版本为一个 Native Project 绑定多个 Tessera Project，还是保持显式唯一归属？
